# 分类与内存模型

> **一句话**：数据结构 = 数据的逻辑关系 + 内存中的物理存储方式。
>
> 关键词：`逻辑结构` `物理结构` `线性` `非线性` `连续` `分散`

## 速查卡

| 维度 | 分类 |
|------|------|
| 逻辑结构 | 线性（数组、链表、栈、队列）、非线性（树、图、堆） |
| 物理结构 | 连续空间（数组）、分散空间（链表） |
| 设计目标 | 省空间、操作快、表示简洁 |
| 底层实现 | 几乎所有结构都由数组、链表或其组合构成 |

## 数据结构定义

数据结构是**组织与存储数据**的方式，包含：

- 数据内容
- 数据之间的关系
- 数据的操作方法

设计时在**空间占用**、**操作速度**、**表示简洁性**之间权衡。

---

## 逻辑结构

### 线性 vs 非线性

| 类型 | 关系 | 代表 |
|------|------|------|
| 线性 | 一对一顺序 | 数组、链表、栈、队列 |
| 树形 | 一对多层次 | 树、堆 |
| 网状 | 多对多 | 图 |

哈希表逻辑上可视为「键 → 值」映射，底层常同时用到数组和链表。

### 生活类比（Hello 算法）

- 地铁线路 → **图**
- 家族谱系 → **树**
- 一摞盘子 → **栈**
- 排队买票 → **队列**
- 字典查词 → **哈希表**

---

## 物理结构

程序运行时数据主要在**内存**中，通过**内存地址**访问。

| 物理结构 | 存储方式 | 优点 | 缺点 |
|----------|----------|------|------|
| 连续（数组） | 相邻内存块 | 随机访问 O(1)、缓存友好 | 中间插删贵、扩容代价 |
| 分散（链表） | 节点 + 指针 | 插删灵活 | 无随机访问、缓存差 |

**所有高级结构都可归结为数组或链表的组合**：

- 栈/队列：数组尾插 或 链表头插
- 哈希表：数组桶 + 链表冲突链
- 堆：数组下标模拟完全二叉树
- 图：邻接表（`vector` 数组）或邻接矩阵

## 基本数据类型（C++）

| 类型 | 典型大小 | 用途 |
|------|----------|------|
| `bool` | 1 字节 | 布尔 |
| `char` | 1 字节 | 字符 |
| `int` | 4 字节 | 整数 |
| `long long` | 8 字节 | 大整数 |
| `float` / `double` | 4 / 8 字节 | 浮点 |

算法实现中，节点值常用 `int`；大规模图用 `int` 存编号，实际对象用符号表映射（并查集讲义中的建模思想）。

## 栈上 vs 堆上（C++）

```cpp
// 栈上：编译期或函数内，自动释放
int arr[100];

// 堆上：运行时分配，需手动或智能指针管理
std::vector<int> vec(100);  // 推荐：RAII 自动管理
```

| 对比 | 栈 | 堆 |
|------|----|----|
| 分配速度 | 快 | 相对慢 |
| 大小 | 有限（通常几 MB） | 受系统内存限制 |
| 灵活性 | 固定或编译期 | 运行时可变 |

做题和工程实现优先 `std::vector`，避免裸 `new[]`。

---

## 缓存局部性

CPU 通过**缓存行**批量加载内存。连续访问（数组）命中率高；跳跃访问（链表）命中率低。

**同一算法阶下，数组实现常比链表快**——这是物理结构带来的常数因子差异，不是逻辑结构本身。

## 例题

**问**：实现一个需要频繁在两端插入删除的队列，选数组还是链表？

**答**：若只需两端操作，用**双向链表**或 `std::deque`（分段连续存储）；单纯 `vector` 头删 O(n)，不合适。

---

## 易错点

| 易错 | 正确做法 |
|------|----------|
| 混淆逻辑结构与物理结构 | 栈是逻辑；可用数组或链表实现 |
| 认为链表插删总是 O(1) | 需已知节点指针；查找仍是 O(n) |
| 忽略缓存 | 大数据量遍历优先连续存储 |
| 静态/动态指长度 | 指数组初始化后长度；链表可运行时扩展 |
